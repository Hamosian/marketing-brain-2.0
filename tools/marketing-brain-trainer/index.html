Why you can trust it

What it does alone, and when it asks

On its own

  • Numbers come with a source and an as-of date.
  • Applies Brand’s standards to decks and docs. The rules were written with Brand, and Brand owns them.
  • Asks before it writes to HubSpot, Monday, or Slack, unless a named automation owns that job.
  • Never publishes the website. It prepares the change and hands a person the publish step.

When it stops to ask

  1. Create this ticket on Marketing Ops Tasks? Yes, create itEdit first

    A confirm prompt. Read what it’s about to write, then say yes or fix it.

  2. UNVERIFIED Plan tier not found in a source

    An UNVERIFIED claim. No source backs it yet. Confirm it or cut it.

  3. HubSpot as of date vs Omni as of date

    Two systems disagree. It shows both, with sources and dates, and says which it used.

Checkpoint 2 of 2

Your launch email says “async recording is Business-plan only.” /demo-reply-fact-check returns UNVERIFIED. What do you do?

Trust it for the right reasons. On its own it sources numbers, applies Brand's own rules, asks before writing to HubSpot, Monday, or Slack, and never publishes the website. When it stops to ask, that's the system doing its job: a confirm prompt, an UNVERIFIED claim, or two systems that disagree. Run the checkpoint: the answer is to confirm the plan tier or cut the claim.

            Upkeep

            How it stays current

            Nobody hand-edits the wiki or the graph. Scripts check the repo and rebuild its views, and two skills turn what people learn into edits.

            1. 1On a skill PR

              Routing check

              A script scores the stored test requests against each skill's description. It fails the build on broken cases and warns when two skills compete for the same words.

              scripts/eval_routing.py

            2. 2On merge to main

              Wiki synced

              The GitHub Wiki regenerates from the repo: pages, links and navigation.

              Knowledge graph rebuilt

              Changed files are re-mapped into the repo graph, and its explorer page rebuilds.

              Doc search index rebuilt

              Every doc is split by heading, and search ranks sections by word match (TF-IDF).

              Plain scripts: no AI model and no API key in this step.

            3. 3When someone learns

              /retro

              Captures what you just learned and commits it to the repo, so the whole team gets it next time.

              /health-check

              Flags system docs not reviewed in 90 days, leftover TODOs, and drift from the templates.

            The point here is that nobody on the team maintains docs by hand. Pull requests get a routing check, every merge rebuilds the wiki, the graph, and the doc search, and all of that is plain scripts. The human part is two skills: retro, which turns a lesson into a repo edit, and health-check, which flags what has gone stale.
