# Impeccable, the vendored design skill

`/impeccable` is Paul Bakaus's design skill for AI coding agents: one skill, 24 sub-commands (`shape`, `audit`, `critique`, `polish`, `typeset`, `layout`, `bolder`, `quieter`, `distill`, `harden`, `animate`, `colorize`, `adapt`, `optimize`, `live`, `generate` and more) and a deterministic detector with 61 rules for the tells every model reproduces (Inter for everything, cards nested in cards, gray text on colored backgrounds, purple-to-blue gradients). Upstream: [github.com/pbakaus/impeccable](https://github.com/pbakaus/impeccable), docs at [impeccable.style](https://impeccable.style).

## Where it lives

`.claude/skills/impeccable/` is a verbatim copy of upstream's own `.claude/skills/impeccable/` directory. The Codex mirror under `.agents/skills/impeccable/` is generated by `scripts/sync-codex.py` like every other skill.

Never edit a file inside the vendored directory. The next update overwrites it, and the repo's reference lint skips it for the same reason (see below). A Riverside-specific rule about how the skill is used belongs in this doc, in `CLAUDE.md`, or in the brand skills.

## When to use it here

This repo is a knowledge base, not a frontend codebase, but it produces UI: hosted HTML deliverables and dashboards, `graphify-out/graph-explorer.html`, the pages `/page-build` and `/webflow-build-agent` assemble, and design reviews of marketing pages. Impeccable is the craft pass on those surfaces. It is not a substitute for the two Riverside skills:

- `riverside-brand-guidelines` stays the single source of truth for color and typography, and `riverside-ux-patterns` for behavior. Load them before `/impeccable`. Impeccable's own first rule is "the brief wins": a pinned palette or typeface overrides its saturated-pattern warnings, so the brand skills are the brief it honors.
- `/impeccable critique` reviews a user interface. `/critique` (the repo's own skill) judges finished writing. The routing table in `CLAUDE.md` carries this disambiguation.
- `/page-cro` diagnoses conversion barriers. Impeccable fixes craft. A conversion question routes to `page-cro` first, and the craft pass follows if the fix is visual.

## First run downloads a binary

The skill's launcher, `scripts/impeccable`, runs a self-contained engine binary. On first use it downloads that binary from upstream's releases into `~/.impeccable/bin/` on the machine running it. Nothing in this repo triggers that download on its own, and the vendoring PR did not run it. Each person decides for their own machine the first time a session calls `impeccable context`. If the launcher fails or is refused, the skill reads existing `PRODUCT.md` and `DESIGN.md` directly and continues, which it announces in one line.

## Deliberately not wired

**The design hook.** Upstream installs a `PostToolUse` (Edit and Write) and `Stop` hook that runs the detector on UI files. Upstream puts it in the local Claude settings file next to the shared one (settings.local, which this repo gitignores), so it is per-developer by design. It is not in the shared `.claude/settings.json`: it would run the downloaded binary after every edit for everyone, and most edits here are Markdown. Turn it on for yourself with `/impeccable hooks on`; it writes the local settings file and `.impeccable/config.json`.

**The four subagents.** Upstream ships `impeccable-finish-reviewer`, `impeccable-asset-producer`, `impeccable-documenter` and `impeccable-manual-edit-applier` under `.claude/agents/`. They are not vendored. `scripts/lint_agents.py` pins every subagent in that directory to Sonnet, requires the harmonized Riverside context block and a registry row, and allows `Bash` only where listed; two of the four carry `Bash` and all four use `model: inherit`. Rewriting third-party agents to pass that lint would fork them. The skill has an in-thread fallback for each under `reference/degraded/`, and that is what runs here. The vendored text only routes to those fallbacks when the harness has no subagent capability at all, and this harness does; so when a step says to spawn one of the four named agents, treat the spawn as unavailable (the Agent tool has no such agent type and the call fails) and run the matching degraded reference instead, disclosing the substitution in one line as the skill requires. Revisit if a `craft` run proves too weak without a fresh-eyes reviewer.

**`/impeccable init`.** It writes `PRODUCT.md` and `DESIGN.md` at the repo root, recording audience, purpose, constraints and the incumbent visual system. It has not been run. Whether this repo has one "product" for its UI output is a team call. If it is run, commit both files; they are team state.

## Repo plumbing

- `scripts/lint_references.py` skips the vendored directory through `VENDORED_DIRS`. Its docs name files the tool creates at runtime (DESIGN.md, the config under .impeccable/, the diff reports), which the lint would otherwise report as dangling.
- `.gitignore` covers the per-developer `.impeccable/config.local.json` and the run artifacts under `.impeccable/live/`, `review/`, `build/`, `mocks/` and `critique/`. The shared config and design token record under `.impeccable/` stay tracked.
- `evals/routing.jsonl` carries three cases: two that must land on `impeccable`, one incumbent guard for `riverside-brand-guidelines`.

## Updating

```bash
git clone --depth 1 https://github.com/pbakaus/impeccable.git /tmp/impeccable
rm -rf .claude/skills/impeccable
cp -R /tmp/impeccable/.claude/skills/impeccable .claude/skills/impeccable
python3 scripts/sync-codex.py
bash scripts/preflight.sh
```

After copying, update the version row above, check that the `SKILL.md` description is still under the router's 1024-character cap (895 at 4.3.1), and re-run the routing eval so a reworded description does not start stealing cases from the brand skills or `page-cro`. If upstream adds new runtime paths under `.impeccable/`, extend the `.gitignore` block.
